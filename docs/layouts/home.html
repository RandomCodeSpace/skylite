A SQL database server where object storage is the source of truth.

skylite is a pre-alpha Go project. The aim is a SQL server on SQLite for Kubernetes pods that have no persistent volumes. The design keeps all durable state in object storage and treats pod disk as a cache. Services will read and write through it over HTTPS.

Pre-alpha. Today the binary prints its version and help, and nothing else. The drawing below is the target design, not working software.

Why it exists

Teams on Kubernetes often want a small relational database for their services, without running a stateful database tier or attaching persistent volumes to pods.

Object storage is already durable, cheap and replicated, and it comes with cloud-native authentication. skylite is designed to make it the source of truth, so that anything inside a pod can be thrown away and rebuilt.

The plan is to build on SQLite rather than a new engine, so the SQL dialect and file format will be SQLite’s own.

The trade, by design

Given up
Low write latency. Each write waits for object storage to confirm it before it is acknowledged.
In return
No stateful tier to operate and no persistent volumes to attach. Durability, replication and access control come from the object store you already run.

What runs today

With a Go toolchain installed, install the binary and ask for its version. That is all it does yet: it prints its version and help.

To build from a clone instead, run make build and then ./bin/skylite version. The getting started guide has both paths.

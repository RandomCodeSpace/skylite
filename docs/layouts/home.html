A SQL database server where object storage is the source of truth.

skylite is a SQL server built on SQLite that keeps all durable state in object storage, with Azure Blob Storage as its primary backend. It needs no persistent volume: its own disk is scratch space. Applications connect over HTTPS with a Go database/sql driver or a JDBC driver.

Beta. The server runs reads, writes and transactions, with leader failover and follower reads. The Azure backend has been tested against a real storage account, failover included; S3 and Google Cloud Storage only against emulators. It has not run on a Kubernetes cluster yet. Releases are signed binaries; there is no container image.

Why it exists

Teams on Kubernetes often want a small relational database for their services, without running a stateful database tier or attaching persistent volumes to pods.

Object storage is already durable, cheap and replicated, and it comes with cloud-native authentication. skylite makes it the source of truth, so that anything inside a pod can be thrown away and rebuilt.

It builds on SQLite rather than a new engine, so the SQL dialect is SQLite’s own.

The trade, by design

Given up
Low write latency. Each write waits for object storage to confirm it before it is acknowledged.
In return
No stateful tier to operate and no persistent volumes to attach. Durability, replication and access control come from the object store you already run.

Try it

Each release has signed binaries for Linux and macOS on amd64 and arm64. The quick start verifies the download, runs a server on a local directory and connects to it from Go and from Java.

With a Go toolchain you can also run go install github.com/RandomCodeSpace/skylite/cmd/skylite@v0.0.3.
